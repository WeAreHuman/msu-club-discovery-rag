src/data_processing.pyClubDataProcessor
process_club_dir(club_dir)Loads profile.json → calls all 3 chunk builders → returns combined list
_profile_chunks(profile)Anchor-body pattern: every sub-chunk starts with "Org / Categories / Status" so it's identifiable even after splitting a long description
_event_chunks(profile)One chunk per event. events_by_month stored as JSON string — Pinecone can't store nested dicts
_constitution_chunks(profile, dir)Regex lookahead on "Article X:" splits at article boundaries without consuming the heading. Each article gets "Org / Constitution — Article N" prefix.
_parse_articles(text)Splits constitution text; preamble (before Article I) becomes Article 0
_find_constitution_txt(profile, dir)Matches doc_id from profile.json → documents/*.txt; fallback: first .txt found
_base_meta(profile)Returns shared flat metadata: org_id, org_name, org_slug, categories[], contact_email, org_url, scraped_at
_split(text, max_tokens)RecursiveCharacterTextSplitter with tiktoken as length_function. Hierarchy: ¶ → \n → . → space → char
_count_tokens(text)tiktoken cl100k_base — must match actual token count; char count would over/under-split
_strip_html(text)Removes HTML tags + html.unescape() — club descriptions arrive as raw HTML from scraper
↓save_checkpoint(slug) written after each successful upsert

WRITE — ingestion path
upsert_chunks(chunks, batch_size=96)Batches records (≤96/call for inference API limit). Returns count upserted; stops early on partial failure so checkpoint is not written.
_make_record(chunk)Flattens {text, metadata} into top-level Pinecone record. Nested dicts are silently dropped by Pinecone — lists of str are OK.
_chunk_id(meta, text){slug}_profile_{i} · {slug}_event_{event_id} · {slug}_constitution_{art}_{i} — deterministic IDs make re-ingestion idempotent (upserts, no duplicates)
delete_namespace()Wipes all vectors in current namespace — called by ingest() when --clear flag is set
READ — chat path
search(query, top_k, filters)Embeds query → cosine similarity search → returns [{id, score, text, metadata}] sorted by relevance
pc.inference.embed(model, inputs)Uses llama-text-embed-v2 — SAME model used at index time. Mismatch = silent garbage results (768-dim vectors get zero-padded to 1024).
index.query(vector, filter, top_k)Mongo-style server-side filtering: {chunk_type:{$eq:"event"}} · {categories:{$in:["Academic"]}}
get_stats()Returns index stats dict (vector count, namespaces)
CHAT PIPELINE  ·  real-time, deployed on Streamlit Cloud
app.pyStreamlit UI — browser entry point
main()Renders hero + example chips. Handles st.chat_input and pending_prompt (from example chips via st.rerun). Dispatches to rag_engine.chat(), updates both session state stores.
initialize_rag_engine()@st.cache_resource — creates ONE RAGEngine per server process. Calls validate_config() first; returns (engine, error) tuple.
render_sidebar()Builds and returns filters dict: {vibe, chunk_type, org_name, top_k}. New Chat button resets both session state stores.
render_assistant_message(msg)Renders: colored vibe badge → answer-box div → citations expanders → debug JSON expander
render_citations(citations)For each citation: expandable [N] Club · type · match% with text snippet and metadata badges
st.session_state (per browser tab)
messages[] — full display state per turn: role, content, citations, vibe, num_chunks, filters_applied
chat_history[] — plain {role, content} for LLM. User content = raw question only (no context blob — keeps history lightweight)
↓rag_engine.chat(question, chat_history, vibe, org_name, chunk_type, top_k)
src/rag_engine.pyRAGEngine — pipeline orchestrator
chat(question, conversation_history, vibe, …)Main multi-turn method. Flow: rewrite query → extract filters → vector search → build context → build messages → generate answer → return {answer, citations, retrieved_chunks}
_rewrite_query(question, history)LLM call (temp=0, max 80 tokens, last 4 msgs only). Resolves "tell me more about the first one" into an explicit standalone query. Skipped entirely on first turn (no history = no ambiguity, saves one API call).
_extract_filters_from_query(query)Keyword regex on the REWRITTEN query. "meeting / event / schedule / when" → {chunk_type:{$eq:"event"}}. Runs after rewrite so references are already resolved.
_build_context_from_chunks(chunks)Formats chunks as "[Source N] OrgName:\n{text}\n". Returns (context_string, citations_list) tuple.
_build_system_prompt(vibe)Returns one of 3 personality strings: scholar / buddy / nofilter. Retrieval is vibe-agnostic — only the prompt string changes. Zero extra latency.
_build_user_prompt(question, context)Injects retrieved context only into the current user message. Prior turns in history are raw questions — prevents quadratic history growth.
query(question, top_k, …)Single-turn version — used by eval/run_eval.py (not the chat UI). Same retrieval logic, no history.
↓generate() for query rewriting  ·  generate_with_history() for final answer
src/llm_client.pyLLM abstraction — swap providers via env var
get_llm_client(provider)Factory function. Reads config.LLM_PROVIDER → returns GroqClient (default) or AnthropicClient. No code change needed to switch providers.
GroqClient.__init__(api_key, model)Initializes Groq SDK. model = config.LLM_MODEL (from .env, currently llama-4-scout-17b-16e-instruct)
generate(prompt, system_prompt, temp, max_tokens)Single-turn. Used by _rewrite_query() at temp=0 for deterministic, fast query rewriting.
generate_with_history(messages, system_prompt, …)Multi-turn. Prepends system prompt to message list, calls Groq chat.completions.create() with full history. Used for the final answer generation.
